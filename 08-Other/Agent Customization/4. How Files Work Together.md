
Think of these files as **different layers of instructions for Copilot**. They do not call each other like Python files. Instead, Copilot **reads them as context** and combines them when generating code.

The flow looks like this:

```text
                    Developer Request
                           |
                           |
                           v

              "Create password reset feature"
                           |
                           |
                           v

              ┌──────────────────────┐
              │   GitHub Copilot     │
              │      Agent           │
              └──────────┬───────────┘
                         |
                         |
        ┌────────────────┼────────────────┐
        |                |                |
        v                v                v


┌────────────────┐ ┌────────────────┐ ┌────────────────┐
│ copilot-       │ │ instructions/  │ │ prompts/       │
│ instructions   │ │                │ │                │
│                │ │                │ │                │
│ Project rules  │ │ Django rules   │ │ Task workflow  │
└───────┬────────┘ └───────┬────────┘ └───────┬────────┘
        |                  |                  |
        |                  |                  |
        └──────────────────┼──────────────────┘
                           |
                           v

                  ┌────────────────┐
                  │    skills/     │
                  │                │
```

# Example Scenario

You ask Copilot:

> "Create user registration API"

---

## Step 1: Copilot reads `copilot-instructions.md`

File:

```
.github/copilot-instructions.md
```

It says:

```markdown
This is a Django project.

Rules:

- Use service layer
- Add tests
- Use type hints
- Follow security practices
```

Copilot now knows:

```
Do not put logic in views.
Create tests.
Follow Django architecture.
```

---

## Step 2: Copilot checks matching instructions

It finds:

```
.github/instructions/django.instructions.md
```

because the file is Python/Django related.

Example:

```markdown
For Django:

Models:
- database only

Views:
- HTTP handling only

Services:
- business logic
```

Now Copilot understands:

Bad:

views.py
```python
def register(request):
    create_user()
    send_email()
    save_database()
```

Good:

views.py
```python
def register(request):
    user_service.register()
```

---

## Step 3: Copilot uses a prompt

You run:

```
/create-django-feature
```

It loads:

```
.github/prompts/create-feature.prompt.md
```

The prompt says:

```
Create:

1. Model
2. Serializer
3. View
4. URL
5. Tests
```

Now Copilot has a checklist.

---

## Step 4: Copilot activates skills

It loads:

```
.github/skills/django-expert/SKILL.md
```

The skill says:

```
You are a Django expert.

Prefer:

models
 ↓
services
 ↓
views
 ↓
urls
```

It also loads:

```
.github/skills/security/SKILL.md
```

because registration involves passwords.

Security skill says:

```
Check:

- password hashing
- validation
- permissions
```

## Short version:

|File|Purpose|
|---|---|
|`copilot-instructions.md`|"How this project works"|
|`instructions/`|"Rules for specific technologies/files"|
|`prompts/`|"Steps for common tasks"|
|`skills/`|"Give Copilot expert knowledge"|
|Source code|The actual Django application|

The important thing: **Copilot does not execute these files. It reads them as context before generating or modifying code.**
