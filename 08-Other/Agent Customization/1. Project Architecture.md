

If you mean **GitHub Copilot project architecture** (using **`.github/copilot-instructions.md`**, **custom instructions**, **prompts**, and **skills**), a real-world structure usually looks like this:

```text
my-project/
│
├── .github/
│   │
│   ├── copilot-instructions.md        # Global instructions for Copilot
│   │
│   ├── instructions/                  # Additional scoped instructions
│   │   ├── python.instructions.md
│   │   ├── frontend.instructions.md
│   │   └── testing.instructions.md
│   │
│   ├── prompts/                       # Reusable prompt templates
│   │   ├── create-feature.prompt.md
│   │   ├── debug-error.prompt.md
│   │   ├── code-review.prompt.md
│   │   └── write-tests.prompt.md
│   │
│   └── skills/                        # Specialized Copilot skills
│       ├── django-expert/
│       │   ├── SKILL.md
│       │   └── examples/
│       │       ├── views.py
│       │       └── models.py
│       │
│       ├── security-review/
│       │   └── SKILL.md
│       │
│       └── database-design/
│           └── SKILL.md
│
├── src/
│   ├── app/
│   ├── models/
│   ├── services/
│   └── utils/
│
├── tests/
│
├── docs/
│   ├── architecture.md
│   └── api.md
│
├── README.md
├── package.json
└── .gitignore
```

## 1. `.github/copilot-instructions.md`

This is the **main brain** of Copilot for your repository.

Example:

````markdown
# Project Instructions

You are working on a Django REST API project.

## Code Style

- Use Python 3.12+
- Follow PEP8
- Use type hints everywhere
- Write clean, readable code

Example:

```python
def get_user(user_id: int) -> User:
    ...

## Architecture

Follow this structure:

- models → database models only
    
- services → business logic
    
- views → HTTP handling
    
- serializers → API formatting
    

Do not put business logic inside views.

## Testing

Every feature must include tests.

Use:

- pytest
    
- pytest-django
    

## Security

Always check:

- SQL injection
    
- authentication
    
- authorization
    
- sensitive data exposure
    

Never hardcode:

- passwords
    
- API keys
    
- tokens
`````

Now whenever Copilot generates code, it follows these rules.

# 2. Scoped Instructions

Inside:

```

.github/instructions/

```

you can create instructions for specific files.

Example:

```

.github/instructions/python.instructions.md

````

```markdown
---
applyTo: "**/*.py"
---

# Python Rules

For Python files:

- Always add type hints
- Use dataclasses when possible
- Avoid global variables
- Add docstrings to public functions
````

Now it only applies to Python files.

---

Example:

```
.github/instructions/frontend.instructions.md
```

```markdown
---
applyTo: "frontend/**/*.{js,ts,tsx}"
---

# Frontend Rules

Use:

- React
- TypeScript
- Functional components

Avoid:

- class components
- inline styles

Prefer:

- Tailwind CSS
```

# 3. Prompt Files

Location:

```
.github/prompts/
```

These are reusable commands.

---

## Example: Create Feature Prompt

File:

```
create-feature.prompt.md
```

```markdown
---
mode: agent
description: Create a new application feature
---

Create a new feature following this workflow:

1. Analyze existing architecture
2. Create required files
3. Add business logic
4. Add tests
5. Update documentation

Before coding:
- explain your plan
- list changed files
```

Then you can call:

```
/create-feature
```

Copilot follows that prompt.

---

## Example: Code Review Prompt

```
.github/prompts/code-review.prompt.md
```

```markdown
---
mode: agent
description: Review code for problems
---

Review this code.

Check:

## Security
- vulnerabilities
- authentication issues

## Performance
- unnecessary database calls
- slow algorithms

## Quality
- readability
- maintainability

Return:

1. Problems found
2. Severity
3. Suggested fixes
```

# 4. Skills

Skills are like **specialized agents**.

Example:

```
.github/skills/database-design/SKILL.md
```

```markdown
# Database Design Skill

You are a database architect.

Your responsibilities:

- design schemas
- optimize queries
- review migrations
- suggest indexes


Rules:

Always consider:

- normalization
- performance
- data integrity
```

---

Example:

```
.github/skills/security-review/SKILL.md
```

```markdown
# Security Review Skill

You are a cybersecurity expert.

Analyze:

- authentication
- authorization
- secrets
- vulnerabilities
- OWASP Top 10

When reviewing code:

1. Find vulnerability
2. Explain impact
3. Provide fix
```

## How Copilot uses them

When you ask:

> "Create a user authentication system"

Copilot combines:

```
copilot-instructions.md
        |
        ↓
backend.instructions.md
        |
        ↓
django skill
        |
        ↓
feature-development prompt
        |
        ↓
Generated code
```

---

Think of it like this:

|File|Purpose|
|---|---|
|`copilot-instructions.md`|Company/project rules|
|`instructions/*.md`|Rules for specific technologies|
|`prompts/*.md`|Repeatable tasks|
|`skills/*/SKILL.md`|Expert roles|
|`README.md`|Human documentation|

A professional AI-assisted repository treats Copilot almost like a **junior developer that has project documentation, coding standards, and expert personas built into the repo**.
