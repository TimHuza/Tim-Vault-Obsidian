# 1. Main Copilot Instructions

File:

```
.github/copilot-instructions.md
```

Example:

```markdown
# Django Project Instructions

You are working on a Django e-commerce application.

## Architecture Rules

Follow this pattern:

Models:
- Database structure only

Views:
- Handle HTTP requests
- No complex business logic

Services:
- Business logic goes here

Serializers:
- API formatting only


## Django Rules

Use:

- Django ORM
- Class Based Views when possible
- Django REST Framework for APIs


## Code Quality

Every function needs:

- Type hints
- Docstrings
- Error handling


## Testing

Every feature must include:

- Unit tests
- API tests


## Security

Always check:

- CSRF protection
- Permissions
- User authentication
- SQL injection
```

# 2. Django Specific Instructions

File:

```
.github/instructions/django.instructions.md
```

````markdown
---
applyTo: "**/*.py"
---

# Django Guidelines


When creating models:

Use:

```python
class Product(models.Model):
    name = models.CharField(max_length=200)
```

Avoid:

```python
class Product:
    pass
```

For views:

Bad:

```python
def checkout(request):
    calculate_price()
    send_email()
    update_database()
```

Good:

```python
def checkout(request):
    order_service.create_order()
```

Business logic belongs in services.

````

The idea is:
```

        ↓
Project rules

        ↓

        ↓
Expert knowledge

prompts/
        ↓
Reusable workflows

        ↓
```

This is close to how a professional Django team would prepare a repository so Copilot behaves like a trained Django developer.
